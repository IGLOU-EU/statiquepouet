StatiquePouet — component showcase

Every selector emitted by the library, rendered live alongside the HTML the rendering layer actually produces. The library ships zero CSS — every visual choice is up to the host page. Two paths from here:

  • Author your own theme. Fork this file, delete the page chrome at the top of the embedded stylesheet, then style the statique-pouet-* selectors however you want.
  • Opt into one of the bundled themes. Add <link rel="stylesheet" href="…/dist/statique-pouet-light.min.css"> (or -dark) and you're done. Both themes are driven by --sp-* CSS custom properties so any value stays overridable with one extra rule in your own stylesheet (no !important, no specificity battle).

Try the themes right here. Use the switcher in the bottom-right of this page to toggle between no theme (raw browser defaults), the bundled light theme, and the bundled dark theme. Your choice is persisted in localStorage.

On this page
  • Author-controlled buttons
  • Alerts (loading, empty, error)
  • Single comment
  • Nested thread (comments list + replies)
  • Instance modal (with native datalist autocomplete)

Convention. Every selector starts with statique-pouet-. The library never adds any other style hook. IDs are used for single-instance elements (#statique-pouet-modal, #statique-pouet-modal-input); everything else is a class.

Author-controlled buttons

The library does not render these — they live in your HTML, with your own classes. You can leave them un-styled (the lib doesn't require any class) or opt into the theme's ready-to-use statique-pouet-button base plus a type modifier:

  • statique-pouet-button-load — prefixes a ⟳ glyph (load / fetch).
  • statique-pouet-button-share — prefixes a ↗ glyph (outbound / share).
  • statique-pouet-button-reply — prefixes a ↩ glyph (reply).

Glyphs are single-codepoint UTF-8 characters injected via ::before — no emoji, no SVG, no icon font, no extra HTTP request. They inherit the button's font size and colour.

The classes only have an effect once one of the bundled themes is loaded (try the switcher in the bottom-right). Without a theme, the buttons fall back to your browser's default <button> chrome — the lib still works perfectly, it just doesn't repaint the controls.

Alerts

Three states, identical structure. Each <p> receives three classes: the common base statique-pouet-alert, a type variant (…-alert-info or …-alert-error), and the semantic class for fine-grained targeting (…-loading, …-empty, …-error).

Single comment

The atomic unit. An <article> with header, content and actions sub-blocks. The data-status-id attribute carries the source post ID for any author script that wants to reach for it.

The statique-pouet-content inner HTML is sanitised by the library (allow-list: p, br, a, span, em, strong; href only allows http(s): / / / # / ?). Mastodon mentions (span.h-card) and hashtags (a.mention.hashtag) pass through with their classes preserved.

Nested thread

The whole comments tree lives inside a single statique-pouet-comments-list container. Each comment may carry a statique-pouet-comment-replies block holding further nested comments — there is no rendering-side depth limit, the library recurses.

Instance modal

Rendered when the user clicks Reply or Share. The modal is a native <dialog> element opened via dialog.showModal(). The browser handles focus trap, ESC-to-dismiss, aria-modal, background inert and focus restoration on close — no JS needed for any of those. The inner box is .statique-pouet-modal-content and the dim is the ::backdrop pseudo-element of the dialog (no element, no class).

On this showcase the dialog is rendered inline via the open attribute (non-modal display, in the document flow). In production the library calls dialog.showModal() instead, which centres the dialog on a fullscreen dim ::backdrop and arms the modal behaviours listed above.

The autocomplete dropdown is a native <datalist> linked to the input via its list attribute. The browser handles the popup, keyboard navigation, accessibility and match highlighting. To see it, click into the input above and start typing or use the arrow keys. The dropdown is not stylable beyond what the browser allows — that's a deliberate trade for the standard behaviour. Suggestions are populated dynamically as the user types by appending <option> elements to the datalist from the result of /api/v1/peers/search.

Customising further

Internal dynamic UI (the suggestions list, the inline error paragraph) is toggled via the standard HTML hidden global attribute — no library-specific class is emitted for show/hide. If your stylesheet sets display: … on the same elements, override with [hidden] { display: none } if needed.

  • The whole selector contract is documented in src/classes.ts. Any change there is a breaking change for downstream stylesheets.
  • The library injects no <style> or <link> element and sets no inline style attributes — every rule comes from your own stylesheet, with no specificity battles to fight.
  • The two bundled themes (dist/statique-pouet-light.min.css, dist/statique-pouet-dark.min.css) expose roughly 40 --sp-* CSS custom properties on :root: colours, spacing, typography, geometry, focus ring, motion. Override any subset in your own stylesheet to retheme without forking. SCSS sources in styles/ if you want to build a third theme from scratch.
  • The bundled themes also include scoped a11y guards: prefers-reduced-motion disables transitions, and forced-colors: active (Windows High Contrast) maps structural boundaries to system colours so the layout survives a forced palette.
